# 内部本地确认恢复：2026-10-04

## 交付范围

新增内部 `PublicationRecoveryService`，将既有 Inspector、冻结结果、一次尝试审批、
共享 PR 互斥和审计接成闭环。保持 Java 协议 java.15、数据库迁移 001–021，不新增
迁移、不更新公网镜像、不写真实 PR、不配置真实恢复密钥。执行器不是 Spring Bean，
没有 API/CLI/启用开关，不能从只读报告直接恢复。

## 提交规则

先验证属于配置认证器的 principal，再读取远端证据；签发与恢复都从实时数据库
构造 Binding，而非接收用户提交的证据 JSON。恢复验证审批后独立登记 requested，
再次读取原 Check 全量批注、摘要正文和修订。所有 GitHub 请求在事务外。

共享 PR 互斥内验证最新 run，锁定 run/job、冻结记录、日志、publication 和摘要
占用；只接纳 failed/PUBLICATION_UNCERTAIN、无锁/租约的任务，要求占用的安装、
仓库、PR 和 run 精确一致。再次校验审批绑定/有效期及原冻结内容指纹。

仅补 confirmed 日志、原目标引用和原 summary，完成 queue/run、递增租约代次、
释放该 run 的精确占用，与成功审计一起原子提交。任一步失败均回滚。没有重发、
重分析、重排队列、模型调用或源代码执行路径。实现复用了既有逻辑；数据库短事务
规范使所有远端读取留在事务外，并沿用现有锁等待/语句超时。

## 验证证据与边界

14 项新增真实 PostgreSQL 17 集成测试通过，GitHub 使用模拟对象，不是新增真实
GitHub 故障注入验收：

- 成功确认原结果和原 summary；已完成任务不能重复恢复。
- 登记后 revision 或远端摘要正文变化拒绝。
- 租约代次变化使旧审批失效，包括两次检查之间的变化。
- 审计追加失败使日志、目标引用、run/queue、代次和占用全部回滚；审批仍已用尽。
- 错误主体在任何 GitHub 读取前拒绝；缺少/持错 PR 互斥不能锁定提交。
- 远端复查后审批过期、新 run 入队或冻结记录删除拒绝。
- 两个不同审批并发恢复，同一 run 只有一次业务/成功审计提交。
- 模拟数据库失败保留 requested，不制造成功/拒绝终态；此项不是实际提交响应丢失演练。
- 摘要占用的 installation 被替换后拒绝，不释放错误占用。

所有恢复集成测试检查 GitHub 调用仅为六种只读方法。测试数据库是独立临时容器，
