# 恢复审计存储基础（2026-10-04）

## 状态

新增迁移 021 与 Java 内部 `PublicationRecoveryAuditStore`，不注册为 Spring bean，
不提供 API/CLI、不接入 Worker/恢复执行器。仍无可写恢复入口、真实身份认证或一次性
审批令牌。本轮没有变更公网 java.13、schema 019、镜像引用或 GitHub 回调。

使用 PostgreSQL 最佳实践中的短事务约束，复用已有 Spring/JDBC 事务设施。不会把
模型、GitHub 或审查分析置入审计事务。

## 实现

- 每次请求绑定随机 attempt UUID、run UUID、主体摘要与证据摘要；摘要限定 64 位
  小写十六进制。理由仅允许固定枚举，不存自由文本、原输出、密文或凭据。
- requested/denied 用 REQUIRES_NEW 独立短事务保存，调用方业务回滚不会抹去拒绝记录。
- 成功审计只能在同一数据源的已打开业务事务内追加；先核对 run/queue 完成、租约
  清空、三项日志已确认、publication 指向对应远端 ID 且自己不再持有摘要占用。
- 审计写入失败向上传播，不吞错，不“尽力记录”；调用方必须回滚全部本地确认。
- 数据库要求终态存在对应 requested，唯一索引限制每次请求最多一个终态，避免重复
  committed/denied 并存。更新被触发器拒绝；应用存储层不提供删除接口。
- 审计随 review run 保留期/仓库删除级联删除。数据库管理权限仍可删除，不能称为
  防篡改归档；主体摘要仍属于敏感运维元数据。

## 明确未完成

存储层接受摘要不是认证，不能用手填身份或本轮的固定测试摘要取得恢复权限。完整
运维身份验证、短时单次审批、动作与快照绑定、成功/失败的审计编排、任务/日志/冻结
记录锁定、同 PR 入队与恢复的互斥、审批消费以及真实可写恢复动作都尚未接入。
本存储状态检查不能替代这些门槛，也没有提供自动重排/强制重发能力。

独立审计事务需要额外连接，不能在持有冲突审计锁或耗尽连接池时嵌套调用。部署候选
需匹配 001–021 的 schema/binary；新旧二进制不可混跑。公网数据库实备、运维密钥
联合恢复、真实新协议 PR 验收及 Phase 0/1 独立证据仍开放。
