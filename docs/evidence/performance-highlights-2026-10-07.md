## 1. 结论先行

项目最值得强调的是 **源码证据驱动的变更理解 + 审查任务与外部发布的异常保护**，不是模型调用次数、浅层规则数量或高 QPS。

本次已经完成可复现的全量/增量对照、本地 HTTP 突发负载与相关回归；也发现了必须保留的负面结果：**真实仓库五次全量/增量集合对照全部不一致**。因此原始 `summary.json` 为 `passed=false`，执行器退出码为 1。这不是压测未跑完，而是正确性门槛没有通过。

可以确认的量化事实：

- 真实冻结 Head 索引覆盖 89 个 Java 文件、1,136 个符号。归档全量快照可筛出来自 6 个未修改文件、指向修改文件的 16 条仓内已解析 CALLS 记录。这是图结构审计，不是独立正确率或页面召回率。
- 250 文件受控样例，单文件修改，复用 240 文件；五次配对集合一致，中位索引耗时 841.23 ms → 186.68 ms，下降 77.81%。该优化在真实仓库未通过一致性验证，暂缓作为正式简历性能成果。
- 本地入口共 150 次正式请求，40 次完成、110 次按单任务保护返回 409，其他失败 0；完成请求整体 P50 4.706 s、P95 5.953 s、最大 7.510 s。不能把拒绝请求计为成功，不能写“支持 8 路并行审查”。
- 7 个 Java 测试套件共 93 项通过；其中发布、客户端重试安全、引擎租约及租约心跳相关 4 个套件合计 58 项。它们是单元/Mock 回归，不是 58 次真实 GitHub 故障或数据库并发实验。

## 4. 不一致诊断：全量也不是真值

诊断与结构审计均在正式负载完成后单独执行，不加入计时样本。

| 观察 | 证据与影响 |
| --- | --- |
| 注解关系跨文件错挂 | 缺失关系中 5,008 条 ANNOTATED_WITH，多出关系中 612 条 ANNOTATED_WITH；全量快照共有 18,879 条注解关系，其中 18,656 条关系的证据路径与来源符号所属文件不一致。不能拿总关系数 29,667 展示有效知识图谱规模。 |
| 注解提取的代码原因 | `indexSelected` 先汇总各文件节点到共享 `symbolByNode`，再针对每个 unit 调用 `extractAnnotations`；后者遍历整个共享 map，却统一写入当前 `unit.path()`，没有限定节点归属。源码与跨文件错挂样例相互印证。 |
| 仓内调用丢失 | 增量相对归档全量少 1 条“两端都在符号表内且已解析”的 CALLS：冻结 Head 的 `ReviewEngine.execute` → `CodeIntelligenceService.analyze`，证据为 ReviewEngine.java:76。冻结源码中存在该调用；确切失效/回退链仍需单独回归定位。 |
| 匿名调用标识不稳定 | 1 条匿名类调用目标含随机 UUID。诊断归一化后仍缺 5,009、多 613 条，因此不是仅有 UUID 格式问题。已有稳定符号测试不能替代关系目标稳定性测试。 |
| 覆盖等级高估 | 同样有 dependency cache/declaration 退化，全量为 SEMANTIC_PARTIAL，增量却标 SEMANTIC。增量覆盖等级计算只检查文件失败/跳过，没有复用全量的构建模型退化判断。 |

原始诊断还记录 CALLS 总差异为缺 2、多 2：其中一对涉及匿名 UUID，另一对涉及调用解析变化。不要把全部 5,010 条差异说成“漏掉 5,010 个真实风险”，也不能把全量当成独立标注真值。

结构审计剔除非 CALLS、未解析及端点不在仓内符号表的关系后，得到 1,392 条仓内已解析 CALLS 记录。其中 16 条来自 6 个未修改文件、指向修改文件。这支持“提供 diff 之外的可定位上下文”的能力方向，但没有测量页面是否全部展示、模型是否使用正确、用户是否节省时间。

## 5. 本地 HTTP 突发负载

64 文件受控仓库，1 次预热不计入正式请求。每组 10 波，等本波所有请求完成再发下一波。每个分析包括 Git 读取、Java 子进程启动、Base/Head 全量索引和上下文构造，不包含浏览器绘制、LLM、数据库和远端发布。单次请求上限 130 s，Java 子进程既有上限 120 s。单活动分析是现有保护策略，没有为数据调整。

| 每波并发 | 正式请求 | 200 完成 | 409 拒绝 | 其他失败 | 完成 P50 s | 完成 P95 s | 成功完成数/s |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 10 | 10 | 0 | 0 | 5.537 | 6.173 | 0.182 |
| 2 | 20 | 10 | 10 | 0 | 4.813 | 5.716 | 0.211 |
| 4 | 40 | 10 | 30 | 0 | 4.200 | 7.510 | 0.222 |
| 8 | 80 | 10 | 70 | 0 | 4.588 | 5.313 | 0.213 |

合计 150 请求、40 完成、110 拒绝。完成时延合并 40 样本：P50 4.706 s，P95 5.953 s，最大 7.510 s。百分位使用 nearest-rank；单组只有 10 个完成样本，P95 等于该组最大值，全部只作描述性数据，不能用于承诺 SLO。

8 路突发下拒绝时延 P50 10.93 ms、P95 63.79 ms；这些快速拒绝没有混入成功时延或吞吐量。各组完成中位时延变化不能解释为并发加速，因为实际分析仍是串行，且存在预热/主机状态影响。

负载期间另有 40 次状态读取，均返回 200，整体 P95 68.60 ms，最大 78.48 ms。标签写入、导出、恶意 Origin 三项均返回预期 403，无效分析输入返回 400。证据只能表述为这轮样本未见额外失败，不能声称长期稳定、100%请求成功或8任务并行。

## 8. 真正亮点及简历措辞

岗位定位：面向 AI 审查工具的 Java 后端实习方向，重点是源码证据、异步任务安全、外部副作用恢复与可验证交付。用户确认“主要负责后端”，但不扩大成独立完成所有实现或主导架构；保留 AI 协作边界。

推荐项目标题：**CodeLens AI｜Java 代码变更理解与审查证据后端**。

可用于项目介绍的三条，正式简历应按篇幅选两条，不堆数字：

1. 主要负责 Java 后端（AI 辅助开发），围绕 Base/Head 提交组织全仓库源码与调用证据；本地冻结仓库审计覆盖 89 个 Java 文件、1,136 个符号，筛出 6 个未修改文件关联变更的 16 条调用记录，补充 diff 之外的审查上下文。
2. 参与审查任务与发布安全建设，通过租约检查、发布意图记录及远端只读核对，约束失效 Worker 和不确定写入的后续操作；本次相关 58 项单元/Mock 回归通过，覆盖租约丢失、写入超时与发布重放等情形。
3. 为本地只读分析建立可复现的资源保护验证：64 文件样例进行 1/2/4/8 路突发共 150 次请求，40 次完成、110 次按单活动任务策略拒绝，完成请求整体 P95 5.95 s；不执行被审查仓库代码，不自动修改源文件。

数字是系统实验结果，不是个人独立编写量；不得改成“我独立完成 58 项测试/全部索引实现”。尚未证明用户能独立讲解每项机制，面试前需复练。

暂不用于正式简历的表述：

- “真实仓库增量提速 77.8%”“全仓审查性能提升 4.5 倍”：受控样例数据被泛化，且真实集合不一致。
- “知识图谱 29,667 条有效关系”：包含已确认的跨文件错误注解关系。
- “8 并发审查无失败”“150 次全部成功”：110 次为保护拒绝，非完成。

一句话面试开场：我主要负责 CodeLens 的 Java 后端，重点不是让模型多写批注，而是给审查提供可定位的跨文件证据，并处理任务失效和远端写入不确定性；这次通过配对基准发现真实增量索引不一致，所以没有把受控样例的提速直接写成项目通用成果。

## 9. 下一步顺序与验收

本轮只新增测量/诊断工具与证据，不改生产解析逻辑、并发策略或发布策略。

1. **先修关系正确性**：限定注解节点的 CompilationUnit 归属；新增跨文件注解路径断言与全量/增量配对回归，避免两个路径共同出错仍被集合一致掩盖。验收包括归属路径冲突为零及已知注解位置断言。
2. **修增量失效与身份稳定**：复现 ReviewEngine 调用缺失，检查完整符号表与子集回退解析差异、已解析/未解析依赖失效；稳定匿名调用目标标识。验收应在相同冻结提交上重复全量、重复增量和配对集合对照，同时保留关系正确性断言。
3. **统一覆盖降级**：增量继承构建模型/依赖完整性退化，不把部分语义标为完整；增加缺依赖、坏缓存、部分失败的配对用例。
4. **修工作台测试就绪诊断**：有界等待明确就绪/提前退出并保留子进程诊断，避免耗尽等待后仅给连接拒绝；不靠无限延长超时掩盖问题。
5. 修复后在同一主机、同样输入、同样堆限制及采样策略完整复测，再更新正式简历的性能数字。不能删掉本轮失败证据。
6. 另行隔离准备数据库压测环境，禁止顺便重启旧公网容器。之后测原子接入、任务抢占、租约失效及发布记录事务；现有 Mock 结果不替代这些实验。
7. 独立精度与真实 Review 时间分别安排，不改变 Phase 0 / Phase 1 的退出条件。本轮没有读取封存 holdout 或关闭质量门槛。
