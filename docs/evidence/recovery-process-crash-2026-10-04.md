# 实际恢复进程终止演练：2026-10-04

## 范围

新增三个测试专用子 JVM 强制终止场景，复用现有恢复服务、审批、审计、PR 锁、
调查和真实 PostgreSQL fixture。正式恢复代码、数据库 migration、pipeline
版本和公网镜像均未改变；没有新 API/CLI/故障开关，没有真实 GitHub 写入。

测试必须显式设置 CODELENS_INTEGRATION_TESTS=true 与 CODELENS_CRASH_TESTS=true，
连接已应用 001–021 的独立 loopback 测试数据库。子进程还要求与
目标 run 相同的测试句柄，检查 recovery-test/fixture、安装 1 和当前协议。
测试辅助入口仅位于 src/test，不打入正式 JAR，不应对 trial/生产数据库运行。

## 三个断点

| 被终止的位置 | 审计 | 业务状态 | 旧审批 |
|---|---|---|---|
| requested 独立提交后 | requested 保留，pending | failed、原日志/引用/代次/slot 保持 | 不可复用 |
| 全部业务修改和成功审计已写入但尚未 commit | requested 保留，成功审计回滚，pending | 事务回滚，原状态保持 | 不可复用 |
| 实际 commit 后但恢复调用尚未返回 | requested+committed 保留 | run/job completed、三个 confirmed、代次+1、slot 释放、原目标保留 | 不可复用 |

每个断点均检查子进程实际存活，强制结束后等待非零退出；只针对 ProcessBuilder
返回的本测试 Process 对象，不按名称找 Java/Worker，不向外部 PID 发送终止。
之后父进程的新事务重新取得 PR 互斥，证明死进程连接/锁已释放，并使用既有
investigate 检查历史结果。提交前尝试重用审批触发唯一约束拒绝；提交后因目标
已完成拒绝。不会自动解锁、重新排队或给旧尝试追加虚假 denied。

审批 bearer 从父进程内存经私有 stdin 管道进入子进程，不进入命令参数、文件或
stdout。父进程只等待固定阶段标记，限制读取输出总量，并始终在 finally 清理
自己创建的进程。子进程的 GitHub 对象仅配置六种只读方法，其他调用会失败，
因此没有网络发布权限、模型调用或受审仓库代码执行。

## 门槛边界

该证据覆盖内部本地确认执行器的 JVM 进程强制退出，不覆盖整机断电、数据库
进程崩溃/故障转移、实际网络丢包、真实 GitHub 中断或长期生产运行。
远端结果仍为 mock；这不能计入 Phase 0/1 的精度、收益或真实样本基线。

备份与发布密钥恢复、受保护运维配置/传输、密钥隔离/轮换、前置拒绝审计、
pending 尝试的人工调查终结策略仍未完成。当前公网仍 java.13/001–019，源候选
java.15/001–021；无冻结记录的历史失败不能补造后强制恢复。
