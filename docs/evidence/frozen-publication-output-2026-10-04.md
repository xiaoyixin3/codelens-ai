# 冻结发布结果：实现与验证（2026-10-04）

## 状态与范围

源码候选 pipeline `java.14`，新增迁移 020。本机公网运行版本仍为 `java.13`，
迁移 001–019；本轮没有升级公网数据库、替换运行镜像或修改 GitHub 权限。
本地 `/readyz` 返回 200，API/PostgreSQL 健康，Worker 仍运行。

此功能是受控恢复的前置条件，不是写入式恢复工具，也不关闭 Phase 0/1 的独立
质量与时间节省门槛。保持 Java 为主，不增加浅层批注规则，不扩大仓库范围。

## 实现

- `CODELENS_FREEZE_PUBLICATIONS=false` 为默认值。启用须通过安全配置提供独立的
  32 字节随机 Base64 `CODELENS_PUBLICATION_KEY`，无需配置实连模型。
- 复用现有 `CredentialVault` 的 AES-256-GCM，不另写加密算法。认证上下文绑定
  installation/run，校验完整输出 SHA-256、任务身份、仓库身份与试运行 neutral 约束。
- 最终 Check 标题、结论、批注、Markdown 与 summary JSON，在首次结果/评论
  发布之前冻结。序列化 UTF-8 明文上限 1 MiB；加密后进入短租约事务。
- 每个 run 仅保留第一份密文，数据库触发器拒绝 UPDATE。重复加密的随机 nonce
  不替换原密文；不同内容拒绝写入。事务内再次校验对应任务、修订和仓库身份。
- 恢复路径复用原值，不重新取 diff、加载策略、索引或调用模型。仍检查当前 base/head
  和已确认的 Check-start ID，并沿用 Check/comment 日志及摘要占用保护。
- 缺密钥、损坏/冲突记录、关闭开关后读到已有记录，或结果写入日志存在但没有冻结
  记录时暂停。禁止补造旧结果。旧版本记录与失败取消输出不强行套用新协议。
- 密文随 review run 保留期/仓库删除级联删除；没有新增输出下载 API。失败信息
  不携带私有正文、密文或解析异常原因。派生输出仍可能包含源码片段，应作为私有数据。

## 实测证据

在一次性 PostgreSQL 17 数据库执行 Java migration 模式，001–020 全部应用并通过
checksum 检查。没有在公网数据库执行迁移。

完整 `release:check` 返回成功：

- Java 共 207 项：203 通过、4 跳过、0 失败/错误；真实 PostgreSQL 集成测试已启用。
- 辅助工具 17 个套件、90 项通过；类型检查、Java/辅助工具构建通过。
- 密钥扫描 329 个文件，0 发现；发布结构检查 `automatedReady=true`，人工门槛仍开放。

新增 14 项测试覆盖：加密往返、随机 nonce、合法长度错密钥/篡改、哈希/任务修订与
仓库身份冲突、UTF-8 大小限制、试运行结论约束、显式配置、原输出及批注复用、禁止
重算/补造、旧修订停止结果发布、冻结失败不发布、冻结先于结果写入、不可变数据库
记录、租约失效及事务回滚、删除级联。部分检查合并在同一测试方法中。

4 项跳过均为显式外部语义验收入口：独立 truth-set、Gson、JUnit4 和源码仓库
验收的系统属性未提供。本轮普通回归通过不替代这些验收，更不证明语义精度或节省时间。

2. 单独演练现有数据库的备份/恢复与 019→020 前向升级。本轮验证是空库全量迁移，
   不冒称已经完成生产备份恢复、旧库升级或新协议真实 GitHub 发布验收。
3. 部署前停止 API/全部 Worker、核对旧任务、备份数据与独立密钥，然后应用迁移并
   启动匹配版本。不在新 schema 下混跑旧二进制，不更新现有试运行镜像标签作假上线。
4. 尚无多密钥/轮换支持；保留与密文及备份匹配的密钥。未启用开关的任务没有冻结保证。
