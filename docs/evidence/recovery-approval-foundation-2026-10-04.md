# 一次性审批基础（2026-10-04）

## 实现范围

新增 Java 内部 `RecoveryOperatorAuthenticator` 与 `RecoveryApprovalService`，不注册
bean，不提供 API/CLI，不读新环境变量，不启用公网配置；无新迁移，候选仍 java.15。

运维认证要求受保护配置的固定主体及随机 32 字节 Base64 bearer，复用现有常量
时间比较。主体对象只能由对应认证实例生成；手填名称、错误凭据或另一实例的主体
不能进入本服务。这是凭据持有者认证，不冒称 OIDC/MFA 或真实人的独立身份验证。

审批复用 CredentialVault 的 AES-256-GCM，不另写加密算法。独立审批 key 不得等于
运维 bearer；与冻结/模型密钥的配置分离仍需未来运维接线校验。令牌限定本地确认、
最长 5 分钟，包含随机审批 UUID 与绑定摘要，认证上下文绑定 run/actor/用途。

绑定涵盖 run/job、安装/仓库/PR、owner/repo、base/head、pipeline、原结果和三个
发布指纹、Check/评论 ID、租约代次、摘要占用 run，以及本地发布引用。SHA 以
40/64 位十六进制限定，其他字符串/摘要均有格式上限。不存正文、自由输入的身份
或密钥；令牌和服务对象的字符串表示被隐藏，令牌校验错误不带底层原因或令牌。
审计持久化错误则必须向上传播，未来运维入口仍需统一脱敏呈现。

首次使用仅向现有审计表写 requested，UUID 唯一约束形成跨同库副本的一次尝试
登记。成功登记后，即使后续业务失败/崩溃，也不能重用；必须调查并重新审批。
没有新建审批表，没有持久化令牌，没有“尽力记录后放行”。

## 验证边界

单元测试覆盖正常绑定、主体/凭据错误、不同认证实例、错误 key、密文篡改、身份/
仓库/job/修订/日志/目标/代次变化、过期与时间回退、审计失败向上传播、无效绑定、
禁止复用运维 key。真实 PostgreSQL 测试验证一次登记并发只有一个成功，以及业务
回滚后仍不能重复登记。测试使用模拟主体/快照与固定的无生产价值密钥。

没有调用 GitHub 或模型，没有实际恢复任务，没有操作公网数据库。

## 尚未完成

服务只验证调用方提供的绑定与令牌，不自行取得真实候选证据。尚需保护运维凭据
配置/传输、执行前真实 GitHub 再核对、持 PR 锁重算审批绑定与过期时间、任务/原文/
日志/占用逐行锁定和比对、原子本地确认与终态审计、拒绝终态编排及端到端故障测试。

有效审批不是恢复动作。当前无对外审批/恢复命令，不允许把旧的只读 JSON 当作
可信最新快照，不允许补造旧输出，也不允许批准重发不确定远端写入。保留期不能
在令牌有效期内删除其唯一使用记录；运维时钟需要同步。旧公网版本保持不变。
